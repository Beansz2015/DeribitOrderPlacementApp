## 1. Deribit `private/edit`: what `amount` means — read before coding

Source: `https://docs.deribit.com/api-reference/trading/private-edit.md`, fetched 2026-10-13 (raw page text). A copy
is in this seat's scratchpad, not in the repo.

Request parameter `amount`, verbatim:
> It represents the requested order size. For perpetual and inverse futures the amount is in USD units. For options
> and linear futures it is the underlying base currency coin. The `amount` is a mandatory parameter if `contracts`
> parameter is missing. If both `contracts` and `amount` parameter are passed they must match each other otherwise
> error is returned.

The order object's `amount` field (the response schema), verbatim:
> It represents the requested order size. For perpetual and inverse futures the amount is in USD units. For options
> and linear futures it is the underlying base currency coin.

The order object's `filled_amount` field, verbatim:
> Filled amount of the order. For perpetual and futures the filled_amount is in USD units, for options - in units or
> corresponding cryptocurrency contracts, e.g., BTC or ETH.

Method description, verbatim:
> Modifies an existing order by changing its price, amount, and/or other properties such as time-in-force, post-only,
> reduce-only, trigger conditions, or advanced order type.
> The order is identified by its order ID. Only open orders can be edited. Changes take effect immediately and may
> result in the order being filled if the new price matches the market.

**Reading.** The page never mentions a partial fill and never says whether an edit's `amount` counts the filled part.
It gives the request parameter the **same words** as the order object's `amount`, which sits beside a separate
`filled_amount` (so `amount` is the order's total, filled part included). That supports the total reading assumed in
`docs/spec-partial-fill-fix.md` §4 F1.

**No escalation.** The page is silent, but not in a way that changes the design. The spec already planned for that
silence: fixtures cover both readings' arithmetic, and §5 item 5 observes it. If Deribit turns out to read `amount`
as the open part, the code over-sizes a **part-filled** leg by its filled part. That needs a part-filled TP or stop,
which testnet cannot make (`TN-F2`). It is an item-5 check (section 5 below).
